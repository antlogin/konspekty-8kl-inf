# Инструкция для проекта публикации (локальные папки, git, Яндекс)

Задача: опубликовать готовые конспекты курса «Информатика 8. Алгоритмы + Python» на сайте Learn-it. Выполнять по порядку; перед необратимыми действиями (push в `main`) показать учителю, что будет опубликовано. Не придумывать значения, которых здесь нет, — спросить учителя.

## 0. Источник

- Репозиторий: `https://github.com/antlogin/konspekty-8kl-inf`. Пока pull request не слит, брать ветку `claude/affectionate-lovelace-yc6y43`; после слияния — `main`. Получить: `git clone -b <ветка> https://github.com/antlogin/konspekty-8kl-inf.git` (файлы по 1 МБ скачивать только через git или архив ветки, не через окно просмотра в приложении Claude: там файл обрезается).
- Готовые конспекты: `K1/K1_Algoritmy_i_ispolniteli.html`, `K2/K2_Sposoby_zapisi_algoritmov.html`, `K3/K3_Ispolnitel_Cherepakha.html` (по одному на урок; новые уроки появляются как `K<N>/K<N>_*.html`).
- **Публикуются только эти `.html`.** Не публиковать и не копировать в публикуемые папки: `K<N>/LOCAL_metodichka_K<N>.md` (служебное учителя), `K1/apps-script/`, `engine/`, `lessons/`, `tools/`, `course.json`, `AUTHORING.md`, `DEPLOY.md`. Методички положить в локальную папку с именем `_Local…` или оставить как файлы `LOCAL_…` (с подчёркиванием): сборка Learn-it их не синхронизирует.

## 1. Что уже настроено (не менять)

- Адрес Google Apps Script (`scriptUrl` в `course.json`) уже подставлен в готовые файлы; кодовые слова групп заданы в свойствах скрипта и в репозитории отсутствуют. Не просить слова, не искать их, не менять `scriptUrl` и `yandexEnabled`.
- Не открывать конспекты на боевом адресе и не выполнять вход/решение задач «для проверки»: события и работы уходят в таблицы учителя на Google Диске. Если проверка входа необходима, попросить учителя выполнить её самому.
- Содержимое конспектов не менять. Если нужна правка текста или вёрстки, описать её и вернуть учителю: правки вносятся в `lessons/K<N>/` и `engine/` с пересборкой (`node tools/build.js K<N>`, `node tools/verify.js K<N>`), правила — `AUTHORING.md`.

## 2. Перенос файлов в локальные исходники

1. Для каждого конспекта найти (или создать по принятому в проекте соглашению) локальную папку занятия курса «Информатика 8». **Одна папка занятия — один конспект** и материалы к нему.
2. Скопировать туда `K<N>/K<N>_*.html` без переименования. При обновлении конспекта заменять файл целиком.
3. Если в папке занятия уже лежит другой конспект (`catalog:type=lesson`), остановиться и спросить учителя.

## 3. Курс и адрес сайта

1. `target` (имя папки курса в репозитории Learn-it) и адрес сайта (строчная латиница, цифры, дефис, вида `<сайт>.learn-it.app`) **выбирает учитель**. До ответа не публиковать. Порядок подключения — `ADD_NEW_COURSE.md` и `PUBLISHING_WORKFLOW.md` из документации Learn-it: запись в `sources.local.json` и `sites.json`.
2. После выбора адреса: в репозитории конспектов в `course.json` заменить `courseUrl` (`https://REPLACE_ME.learn-it.app/` → `https://<сайт>.learn-it.app/`), выполнить `node tools/build.js --all`, заново скопировать `.html` по п. 2 и закоммитить `course.json` и обновлённые `K<N>/`. Адрес сайта в конспектах только сохраняется в данных; на вход и отправку результатов он не влияет.

## 4. Сборка и публикация

1. `npm run update`, затем проверка через `npm run dev`:
   - в каталоге появились конспекты с названиями «Алгоритмы и исполнители. Свойства алгоритмов», «Способы записи алгоритмов. Блок-схемы. Среда Python», «Исполнитель «Черепаха» (turtle). Линейный алгоритм» (без «Занятие N» в названии);
   - порядок конспектов в каталоге К1, К2, К3 соответствует порядку занятий; при необходимости задать `catalog:number` только по согласованию с учителем;
   - строка пути «learn-it.app › курс › номер» вставлена сборкой и не перекрывает форму входа; при проверке открыть страницу и убедиться, что форма отображается и страница не пустая;
   - размер файлов около 1,1 МБ не отвергается синхронизацией (проверить журнал `sync`).
2. Показать учителю итог (какие файлы и в какой курс попадут), получить подтверждение и выполнить `git push` в `main`. Дождаться завершения GitHub Actions.
3. Открыть опубликованный адрес каждого конспекта (без входа и без ввода данных) и проверить:
   - форма входа отображается; консоль без ошибок (кроме ожидаемых сетевых ошибок, если нет связи);
   - запросы идут только на `script.google.com` (после действий пользователя) и к счётчику Метрики, вставленному сборкой; других внешних адресов нет;
   - меню «План занятия, Повторение, Теория, Разбор кода, Практикум, Итог» переключается; на ширине 390 px нет горизонтальной прокрутки.

## 5. Отчёт учителю

Перечислить: какие файлы опубликованы и по каким адресам; что проверено; что не удалось проверить (например, вход с кодовым словом выполняет учитель); что осталось сделать (замена заглушки `courseUrl`, если адрес сайта ещё не выбран).

## 6. Обновление уже опубликованного конспекта

Получить свежую версию репозитория (`git pull`), скопировать изменённые `K<N>/K<N>_*.html` в локальные папки занятий, `npm run update`, проверка по п. 4, `git push`. Не править собранные HTML вручную (кроме экстренного случая по просьбе учителя): исходники в `lessons/` и `engine/`, иначе правка потеряется при следующей сборке.
