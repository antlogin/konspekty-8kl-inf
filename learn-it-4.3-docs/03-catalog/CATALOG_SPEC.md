# Спецификация каталога и синхронизации

**Версия пакета:** Learn-it 4.3  
**Статус:** реализованная текущая схема

## 1. Область

Документ определяет поведение:

```text
scripts/sync.js
scripts/build-catalog.js
templates/index.html
sources.local.json
sites.json
<course>/catalog.json
<course>/index.html
```

Главная страница learn-it.app собирается отдельно, см. [HOME_PAGE_SPEC.md](HOME_PAGE_SPEC.md).

Структура каталога курса (строка на конспект, порядковые номера, общие материалы) и навигация между главной, курсом и материалом заданы в [NAVIGATION_SPEC.md](NAVIGATION_SPEC.md). При расхождении с этим документом в вопросах структуры и порядка приоритет у NAVIGATION_SPEC.

## 2. Общий pipeline

```text
source-папки
   ↓ sync.js --prune
папки курсов в репозитории
   ↓ build-catalog.js
catalog.json + готовый index.html
```

Штатная команда:

```powershell
npm run update
```

Логически:

```text
node scripts/sync.js --prune
node scripts/build-catalog.js
```

## 3. Разрешённые публичные типы файлов

Белый список текущей синхронизации:

```text
.html
.pdf
.png
.jpg
.jpeg
.gif
.webp
.svg
.avif
```

Остальные форматы не должны автоматически попадать в target. PowerPoint, рабочие документы, ZIP и иные исходные/служебные файлы остаются вне опубликованной копии, пока их тип явно не добавлен в архитектуру.

## 4. Ограничение PDF

```text
PDF > 10 MiB → не синхронизировать
```

Пропуск большого PDF должен сопровождаться диагностическим сообщением pipeline.

## 5. Локальные Archive ZIP

Любое имя, соответствующее регистронезависимому шаблону:

```text
Archive*.zip
```

считается локальным архивом.

Примеры:

```text
Archive.zip
Archive_old.zip
archive_backup.zip
ARCHIVE_previous.zip
```

Такие файлы:

- не копируются из source;
- при `--prune` удаляются из target, если оказались там ранее.

Это отдельное постоянное правило, даже несмотря на то, что ZIP не входит в текущий whitelist.

## 5a. Служебные файлы и папки учителя (`LOCAL_*`, `local*`, `_local*`)

Ключи ответов, варианты контрольных, просмотрщики результатов и другие материалы только для учителя живут в рабочей папке и никуда не публикуются.

```text
LOCAL_*            файл (регистр любой, обязательно с подчёркиванием)
local*/, _local*/  папка на любом уровне, регистр любой (например, _Local-Data)
```

Такие файлы и папки:

- `sync.js` не копирует; при `--prune` удаляет их из репозитория, если они туда попали;
- `.gitignore` не даёт закоммитить;
- `scripts/deploy-yandex.sh` не публикует и удаляет из бакета, если они там уже есть.

Файлы `LOCAL-*` (с дефисом) правилом **не** покрываются и публикуются.

## 6. Корневой `index.html`

Корневой `index.html` исходной папки курса не является публикуемым источником главной страницы.

```text
source/index.html → не копировать
```

Итоговый:

```text
<target>/index.html
```

создаёт `build-catalog.js` из общего `templates/index.html`.

Вложенный учебный HTML с другим путём/именем обрабатывается как обычный материал.

## 7. Метаданные HTML

Обязательные:

```html
<meta name="catalog:title" content="Название">
<meta name="catalog:type" content="lesson">
```

Необязательные:

```html
<meta name="catalog:topic" content="">
<meta name="catalog:description" content="">
<meta name="catalog:tags" content="">
<meta name="catalog:order" content="">
<meta name="catalog:hidden" content="">
<meta name="catalog:legacy" content="">
<meta name="catalog:number" content="">
<meta name="catalog:parent" content="">
<meta name="catalog:nav" content="">
```

`catalog:hidden=true` исключает отдельную запись каталога, но не публикацию файла.

`catalog:number`, `catalog:parent`, `catalog:nav` описаны в [NAVIGATION_SPEC.md](NAVIGATION_SPEC.md).

## 8. Статический `index.html`

Главное архитектурное правило:

> список материалов должен быть полностью доступен без JavaScript.

`build-catalog.js` вставляет в итоговый HTML готовый список:

```html
<ul class="catalog-list">
  <li class="catalog-item" id="n-7">...</li>
</ul>
```

С 4.3 список строится по конспектам, от новых к старым, номер выводится текстом, материалы к конспекту — ссылками внутри его строки, общие материалы — отдельным блоком (см. [NAVIGATION_SPEC.md](NAVIGATION_SPEC.md), раздел 5). Нумерованный `<ol>` не используется.

Основные переходы — обычные `<a href="...">`.

`catalog.json` сохраняется, но главная страница не должна зависеть от `fetch('./catalog.json')` для базового отображения.

## 9. Progressive enhancement

Без JavaScript:

```text
видны все материалы и все ссылки работают
```

С JavaScript дополнительно доступны:

```text
поиск
фильтр по теме
фильтр по типу
```

Элементы фильтрации по умолчанию должны быть скрыты и показываться только после подтверждения работы JavaScript, если именно так устроен общий шаблон.

Клиентский код каталога следует держать консервативным и не делать современные JS-возможности обязательными для навигации.

## 10. Legacy metadata

Основной материал:

```html
<meta name="catalog:legacy" content="material_Legacy.html">
```

Legacy-файл:

```html
<meta name="catalog:hidden" content="true">
```

Принцип:

```text
один материал = одна строка каталога
```

## 11. Проверка Legacy-ссылки

`build-catalog.js` должен:

1. прочитать `catalog:legacy`;
2. разрешить его относительно основного HTML-файла;
3. отклонить абсолютный URL;
4. отклонить выход выше корня курса через `../`;
5. проверить существование файла;
6. при ошибке выдать предупреждение и не создавать битую ссылку.

Типовые предупреждения:

```text
⚠ <file>: некорректный catalog:legacy="..." — ссылка не добавлена
⚠ <file>: legacy-файл не найден: ...
```

## 12. Данные Legacy в `catalog.json`

Для материала с Legacy сохраняются поля:

```json
{
  "legacy": "material_Legacy.html",
  "legacyUrl": "resolved/path/material_Legacy.html"
}
```

Точная совокупность остальных полей определяется текущим генератором. При отсутствии Legacy значения должны интерпретироваться как отсутствие дополнительной ссылки, а не как второй материал.

## 13. Отображение Legacy

В строке основного материала используется компактная ссылка:

```text
HTML | lite
```

Зафиксированный визуальный размер SVG:

```text
78 × 18 px
```

Ссылка остаётся обычным `<a href>`. Доступность:

```text
title="Версия для старых браузеров"
aria-label="Версия для старых браузеров"
```

Под SVG сохраняется текстовый fallback:

```text
HTML lite
```

Следовательно, даже при проблемах SVG ссылка остаётся понятной и работоспособной.

## 14. Шаблон каталога

Актуальные маркеры общего шаблона:

```text
{{SITE_TITLE}}
{{SITE_SUBTITLE}}
{{CATALOG_COUNT}}
{{CATALOG_ITEMS}}
{{TYPE_FILTERS}}
{{TOPIC_OPTIONS}}
```

Генератор проходит по курсам, зарегистрированным в `sites.json`.

## 15. Генерируемые файлы

Эти файлы не являются ручными источниками:

```text
<course>/catalog.json
<course>/index.html
```

При `npm run update` они могут быть пересозданы. Ручные изменения в них следует переносить в `build-catalog.js` или `templates/index.html`, иначе они будут потеряны.

## 16. Совместимость каталога

Базовая разметка каталога должна использовать обычные HTML-элементы. Основная навигация не должна требовать Web Components, SPA-router, `fetch`, Promise или ES modules.

Современный CSS/JS может применяться только там, где его отсутствие не разрушит базовое отображение и переходы.

## 17. Диагностический цикл

После изменения общих скриптов:

```powershell
npm run update
npm run dev
```

Проверить:

- несколько разных курсов;
- каталог без JavaScript;
- поиск/фильтры с JavaScript;
- материал без Legacy;
- материал с Legacy;
- отсутствие битой Legacy-ссылки;
- отсутствие лишних исходных файлов;
- `git status` перед публикацией.

## 18. Нормативные правила

```text
[ ] список материалов есть в HTML без JS
[ ] catalog.json не является обязательным runtime-источником списка
[ ] скрытый HTML публикуется, но не получает строку
[ ] Legacy проверяется до генерации ссылки
[ ] Archive*.zip никогда не публикуется
[ ] файлы LOCAL_* и папки local*/_local* не синхронизируются и не публикуются
[ ] PDF > 10 MiB не публикуется автоматически
[ ] root source index.html не копируется
[ ] index.html и catalog.json генерируются общими скриптами
[ ] номер есть только у конспектов и не меняется после первой публикации
[ ] материалы к конспекту не получают отдельной строки и номера
[ ] в опубликованных материалах есть строка пути (кроме catalog:nav=off)
```
