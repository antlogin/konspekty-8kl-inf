# Публикация учебных курсов

**Версия пакета:** Learn-it 4.3

## 1. Общая схема

Все сайты публикуются из общего репозитория:

```text
antlogin/My-cources-catalog, ветка main
```

```text
source
→ npm run update   (sync.js --prune → build-catalog.js → build-home.js)
→ локальная проверка (npm run dev)
→ git commit + git push
→ GitHub Actions «Deploy to Yandex Cloud»
→ бакеты Yandex Object Storage
→ https://<сайт>.learn-it.app и https://learn-it.app
```

Каждый класс имеет:

1. отдельную локальную source-папку;
2. отдельную target-папку в репозитории;
3. запись source → target в локальном `sources.local.json`;
4. запись в `sites.json`;
5. свой бакет `<сайт>.learn-it.app`, который создаётся автоматически при первой публикации.

Главная страница — папка `home/`, бакет `learn-it.app`.

## 2. Source и target

Исходные материалы находятся вне Git-репозитория, например:

```text
D:\_Work\online-FSH\PHYS-7kl_26-27
```

Общий репозиторий, например:

```text
D:\_Misc\_PetProjects\My-cources-catalog
```

Target:

```text
7-physics
```

## 3. `sources.local.json`

Пример mapping:

```json
{
  "source": "D:/_Work/online-FSH/PHYS-7kl_26-27",
  "target": "7-physics"
}
```

Правила:

- в Windows-путях JSON использовать `/`;
- `target` относителен корню репозитория;
- `sources.local.json` не коммитится;
- файл нужен только на локальной рабочей машине.

## 4. Синхронизация

Публикуются автоматически только:

```text
.html .pdf .png .jpg .jpeg .gif .webp .svg .avif
```

Дополнительно:

```text
PDF > 10 MiB → пропустить
Archive*.zip → всегда пропустить
LOCAL_*      → всегда пропустить (служебные файлы учителя, только локально)
local*/, _local*/ → папка пропускается целиком (например, _Local-Data)
source root index.html → не копировать
```

Подробности: [CATALOG_SPEC.md](../03-catalog/CATALOG_SPEC.md).

### Локальные файлы `LOCAL_*`

Файлы, имя которых начинается с `LOCAL_` (например, `LOCAL_trig-11-results.html` для просмотра результатов тренажёра), живут только в рабочей папке: `sync.js` их не копирует и удаляет из репозитория при `--prune`, а `.gitignore` не даёт закоммитить их даже случайно.

То же правило действует для папок: папка, имя которой начинается с `local` или `_local` в любом регистре (например, `_Local-Data` с вариантами контрольной и ключом для учителя), не копируется в репозиторий целиком, при `--prune` удаляется оттуда, игнорируется git, а `deploy-yandex.sh` не публикует её и удаляет из бакета, если она туда уже попала.

### Источник истины — рабочая папка

Синхронизация идёт только в одну сторону: рабочая папка (source) → репозиторий (target). Если урок изменён прямо в репозитории (вручную, в PR или Claude), следующий `npm run update` перезапишет его старой версией из рабочей папки.

Поэтому после любой правки урока в репозитории:

1. `git pull`;
2. скопировать изменённые файлы обратно в рабочую папку (тот же относительный путь);
3. только после этого запускать `npm run update`.

Пример: в октябре 2026 формы отправки в 15 уроках перевели с Netlify на Yandex прямо в репозитории, и их пришлось вернуть в рабочие папки, иначе sync откатывал правку.

## 5. Полное локальное обновление

```powershell
cd D:\_Misc\_PetProjects\My-cources-catalog
npm run update
```

Команда выполняет синхронизацию с `--prune`, пересборку каталогов классов и главной страницы. После неё `catalog.json`, `index.html` классов и `home/index.html` — производные файлы, вручную их не правят.

Только главная: `npm run home`.

## 6. Локальная проверка

```powershell
npm run dev
```

Проверить:

- страницу нужного класса и список материалов;
- переходы, порядок и заголовки;
- поиск и фильтры;
- каталог с отключённым JavaScript;
- Legacy-ссылки;
- отсутствие лишних исходных файлов;
- при изменении `sites.json` — главную `home/index.html`.

Остановить сервер: `Ctrl+C`.

## 7. Git

```powershell
git status
git add .
git status
git commit -m "Update course materials"
git push
```

Перед commit убедиться, что `sources.local.json` не staged.

Предупреждение `LF will be replaced by CRLF` само по себе не ошибка.

## 8. Автоматическая публикация

После `git push` в `main` запускается GitHub Actions → **Deploy to Yandex Cloud**:

- публикуются только папки, изменённые в этом push (включая `home/`);
- если изменён `sites.json` — публикуются все сайты и главная;
- для каждого сайта: при необходимости создаётся бакет, включается режим сайта (`index.html`), файлы синхронизируются с удалением лишних;
- доступ к бакету: файлы читаются публично (флаг `--public-read` через `yc`), список файлов закрыт (`--public-list=false`), ACL бакета `private`. После публикации скрипт проверяет, что `index.html` отдаёт 200 (иначе возвращает ACL `public-read` с предупреждением), и предупреждает, если листинг всё ещё открыт;
- служебное учителя (`LOCAL_*`, папки `local*`/`_local*`) не публикуется и удаляется из бакета, если оказалось там;
- `.html` и `.json` получают `Cache-Control: no-cache`, остальные файлы — `max-age=3600`;
- `netlify.toml`, `.gitkeep`, `.DS_Store` не публикуются;
- если заданы `YC_CERT_ID` и `YC_SA_KEY_JSON`, к бакету привязывается HTTPS-сертификат.

Ход публикации: GitHub → репозиторий → вкладка **Actions** → последний запуск. Зелёная галочка — опубликовано.

Проверить, что лишнего не опубликовано: `https://storage.yandexcloud.net/<бакет>/?list-type=2` должен отвечать 403.

### Если запуск висит в очереди

Иногда GitHub долго не выделяет сервер для Actions (так было вечером 05.10.2026). Это сбой на стороне GitHub, а не в коде или ключах:

1. Проверить https://www.githubstatus.com — жёлтая или красная плашка у Actions означает сбой.
2. Запуск, который не начался примерно за 15 минут, GitHub отменяет сам.
3. Когда сбой пройдёт: **Actions** → **Deploy to Yandex Cloud** → **Run workflow**. Ручной запуск публикует все сайты, так что ничего не потеряется.

Если ждать нельзя — публикация без GitHub (ниже).

### Опубликовать всё вручную

GitHub → **Actions** → **Deploy to Yandex Cloud** → **Run workflow** → ветка `main` → **Run workflow**.

### Публикация без GitHub (аварийный вариант)

Нужны aws CLI, jq, статический ключ и авторизованный `yc`:

```bash
export AWS_ACCESS_KEY_ID=… AWS_SECRET_ACCESS_KEY=… SITE_DOMAIN=learn-it.app YC_CERT_ID=fpqgqvhqgfmqtrv4jn53
yc config set service-account-key authorized_key.json   # ключ claude-admin
yc config set folder-id b1gof7bq8juoj91v6ngh
scripts/deploy-yandex.sh 9-physics      # один сайт
scripts/deploy-yandex.sh home           # только главная
scripts/deploy-yandex.sh                # все
```

**Важно:** без авторизованного `yc` скрипт ставит бакету ACL `public-read`, и список файлов снова становится открытым (в логе будет предупреждение). Если пришлось публиковать без `yc`, после восстановления GitHub сделать ручной **Run workflow**: он закроет листинг обратно.

Рабочий статический ключ лежит только в секретах GitHub. Для аварийной публикации выпускается временный:

1. https://console.yandex.cloud/ → каталог `trainer-telemetry` → **Identity and Access Management** → **Сервисные аккаунты** → `claude-admin`.
2. **Создать новый ключ** → **Создать статический ключ доступа**, в описании «временный <дата>». Секрет показывается один раз.
3. Опубликовать.
4. Сразу удалить временный ключ: тот же аккаунт → ключ с описанием «временный…» → `⋯` → **Удалить**. Ключ GitHub не трогать.

## 9. Обычный цикл

```powershell
npm run update
git status
git add .
git commit -m "Update course materials"
git push
```

Через одну-две минуты изменения видны на сайте. Если браузер показывает старую версию — `Ctrl+F5`.

## 10. Каталог и публикация — разные понятия

`catalog:hidden=true` означает:

```text
файл опубликован
+ доступен по прямой ссылке
- не имеет отдельной строки каталога
```

Это используется для Legacy и вспомогательных HTML-страниц.

## 11. Телеметрия не проходит через хостинг

Бакеты отдают только статический HTML. События тренажёра и `result_submitted` идут напрямую из браузера в Telemetry API. Ученические файлы в базовой архитектуре сохраняются локально.

## 12. Netlify

Netlify-проекты классов остались от схемы v1.x. Они больше не являются каналом публикации: ученикам даются только адреса `*.learn-it.app`. Пока проекты не отключены, Netlify продолжает собирать предпросмотры для PR; их можно отключить в настройках каждого проекта (Deploy Previews → None) или удалить проекты целиком. Файлы `netlify.toml` в папках классов можно удалить после отключения Netlify.

## 13. Проверка перед публикацией

```text
[ ] npm run update завершился без критических ошибок
[ ] проверен нужный index.html
[ ] Legacy warning отсутствует для валидных материалов
[ ] каталог работает без JS
[ ] git status просмотрен
[ ] «Каталог курса» и ссылки между уроками открываются (нет 404, нет *.netlify.app)
[ ] служебное учителя — в LOCAL_* или папке local*/_local*
[ ] sources.local.json не staged
[ ] commit содержит только ожидаемые изменения
[ ] git push выполнен
[ ] в GitHub Actions запуск «Deploy to Yandex Cloud» зелёный
[ ] адрес https://<сайт>.learn-it.app проверен
```
