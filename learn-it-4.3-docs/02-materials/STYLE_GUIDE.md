# Правила оформления и стиля учебных материалов

**Версия пакета:** Learn-it 4.3  
**Согласовано:** 2026-10-12

Документ задаёт, как выглядит и как написан учебный материал: вёрстка текста, язык, термины, заголовки, задания, типографика формул и бумажные листы. Технические требования к странице (цвета, геометрия, размеры, доступность) остаются в [HTML_MATERIAL_SPEC.md](HTML_MATERIAL_SPEC.md); при расхождении по вёрстке текста действует этот документ.

Правила действуют для всех курсов. Правила собраны из замечаний по курсам физики, алгебры, информатики, SciTime и JavaScript.

## 1. Вёрстка страницы

### 1.1. Длинные строки на широком экране недопустимы

- Основной текст на компьютере набирается в две колонки, начиная с compact desktop (окно шире 720 CSS px). На телефоне одна колонка.
- Одиночный абзац между блоками (вводная фраза, связка) ставится в узкую колонку около 680 px (70–80 знаков в строке), а не на всю ширину.
- Абзацы и определения не растягиваются на всю ширину контента (1120 px). Задания (вопросы работ, тренажёры, самопроверка) не сужаются до одной колонки с пустым полем, а раскладываются в две колонки (п. 1.2).

### 1.2. Парные блоки рядом

- Определение и формула, алгоритм и типичная ошибка, термин и пояснение ставятся рядом, в две колонки. Задания на компьютере верстаются в две колонки, на телефоне (до 720 px) в одну:

  | Тип задания | Левая колонка | Правая колонка |
  |---|---|---|
  | С рисунком (шкала, схема) | рисунок, около 260 px (210 px в compact) | подсказка, варианты или строки сопоставления |
  | С широким рисунком (линейка) | рисунок | ответы; колонки равные |
  | Выбор нескольких ответов без рисунка | варианты ответа сеткой 2 × N, на всю ширину задания | |
  | Сопоставление без рисунка | список ответов с буквами (А, Б, В…) | строки с выбором буквы |
  | Тренажёр | условие (и мини-схема) | кнопки ответа и сообщение проверки |
  | Задания для самопроверки | нумерованный список в две колонки | |

  Формулировка задания и сообщение проверки идут над и под колонками; ширина строки в колонке не превышает ~680 px автоматически.

  ```css
  .q-cols { display: grid; grid-template-columns: minmax(0,1fr) minmax(0,1fr); gap: 12px 24px; align-items: start; }
  .q-cols.fig { grid-template-columns: minmax(0,260px) minmax(0,1fr); }
  .q-opts { display: grid; grid-template-columns: repeat(2, minmax(0,1fr)); gap: 8px 16px; }
  .qt-grid { display: grid; grid-template-columns: minmax(0,1fr) minmax(0,1fr); gap: 12px 24px; }
  .selfcheck ol { display: grid; grid-template-columns: repeat(2, minmax(0,1fr)); gap: 0 36px; }

  @media (max-width: 720px) {
    .q-cols, .q-cols.fig, .q-opts, .qt-grid, .selfcheck ol { grid-template-columns: 1fr; }
  }
  ```

- На телефоне колонки идут друг под другом.
- Определение оформляется отдельным блоком (термин и формулировка), а не растворяется в сплошном тексте.

### 1.3. Таблицы

- Ширина таблицы ограничена: около 920 px. Длинные подписи к моделям тоже делятся на две колонки.
- Код в ячейке не переносится посреди конструкции: вместо этого колонка шире.

### 1.4. Выравнивание и абзацы

- Крупные блоки текста (основной текст, врезки «Вывод», подписи к моделям, абзацы в карточках): выравнивание по ширине, красная строка 1,5 em, автоматические переносы (`hyphens: auto`, у страницы `lang="ru"`).
- Короткие подписи, панели, таблицы, шкалы: по левому краю.
- Телефон в вертикальной ориентации: по левому краю, красная строка сохраняется.
- Выравнивание по ширине не должно ломать двухколоночный набор.

Пример:

```css
.prose { column-count: 2; column-gap: 28px; }
.prose p { text-align: justify; text-indent: 1.5em; hyphens: auto; }
.prose-narrow { max-width: 680px; }

@media (max-width: 720px) {
  .prose { column-count: 1; }
  .prose p { text-align: left; }
}
```

### 1.5. Размеры шрифтов

По [HTML_MATERIAL_SPEC.md](HTML_MATERIAL_SPEC.md), разделы 10–12, крупнее не делать. На 721–1400 CSS px основной текст 14 px.

### 1.6. Графики

На компьютере ширина графика не больше примерно 560 px, на телефоне во всю ширину.

### 1.6.1. Рисунки приборов соответствуют реальным приборам

- Нулевая отметка мензурки совпадает с дном: пустой мензурке соответствует 0 мл. Ноль термометра и динамометра — на месте, соответствующем реальному прибору.
- Деления равномерные, крупные штрихи подписаны, число промежутков между подписанными штрихами совпадает с условием задания.
- Уровень жидкости (нижний край мениска), конец столбика или указатель стоит точно на штрихе, который даёт верный ответ.
- Шкала строится программно из параметров (цена крупного деления, число промежутков, начальное значение, показание), а не рисуется вручную; ответ в задании вычисляется из тех же параметров.

### 1.7. Горизонтальная прокрутка на телефоне недопустима

Длинная выкладка разбивается на строки или нумерованный список. Формула шире экрана разбивается по знакам «=» (раздел 6.2).

### 1.8. Низ страницы

Футер не нужен, внизу страницы ничего не пишется. Блоки «Термины занятия» и «Следующее занятие» не ставятся.

### 1.9. Навигация

- Крупные части занятия (теория, тренировка, практикум) — отдельные переключаемые страницы внутри одного HTML-файла. Из любого раздела в любой другой переход в один щелчок: меню в шапке и кнопки «Назад» / «Далее» внизу раздела. Название страницы вида «Метод 1: теория» стоит в левом верхнем углу.
- Пункты меню в шапке короткие и помещаются в одну строку. Пункта «Ученик» нет; «Домашнее задание» сокращается до «ДЗ».

### 1.10. Страница для показа классу

Страница, которая выводится на экран в классе (например, прогресс выполнения), содержит только таблицу, легенду цветов и время обновления: без подзаголовков, пояснений и технических сообщений. Название: «Прогресс работы».

### 1.11. План занятия

- Блок называется «План занятия» (не «Маршрут занятия»); пункт меню — «План занятия», он первый в меню.
- На компьютере уроки стоят в две колонки: «Урок 1» слева, «Урок 2» справа; на телефоне друг под другом.
- Перемена обозначается одним словом «Перемена», без пояснений («Отдых по расписанию» не пишется). Она ставится последней строкой колонки «Урок 1», отделённой тонкой линией.
- Блок «Планируемый результат» на компьютере уже основной колонки текста примерно на 20 % (около 544 px вместо 680 px) и выровнен по центру карточки; на телефоне во всю ширину.

Эталонная разметка и CSS:

```html
<section id="route" class="card"><h2>План занятия</h2>
  <div class="route">
    <div class="route-lesson"><div class="time">Урок 1</div><ul>…</ul><div class="time route-break">Перемена</div></div>
    <div class="route-lesson"><div class="time">Урок 2</div><ul>…</ul></div>
  </div>
  <div class="note route-goal"><b>Планируемый результат.</b> …</div>
</section>
```

```css
.route { display: grid; grid-template-columns: minmax(0,1fr) minmax(0,1fr); gap: 10px 28px; align-items: start; }
.route .route-break { margin-top: 10px; padding-top: 8px; border-top: 1px dashed var(--line); }
.note.route-goal { max-width: 544px; margin: 16px auto 0; }

@media (max-width: 720px) {
  .route { grid-template-columns: 1fr; }
  .note.route-goal { max-width: none; }
}
```

## 2. Тон и регистр

### 2.1. Академический, но простой язык

- Строгий язык хороших учебников по предмету: без разговорных и просторечных оборотов, жаргона, языковых ошибок и упрощений по сути.
- Фразы короткие и простые. Книжные обороты («является», цепочки отглагольных существительных) по минимуму, длинные назывные конструкции упрощаются.

### 2.2. Без обращения на «ты», восклицаний и игровых слов

### 2.3. Пояснения безличны

- Без обращений к ученику и призывов («Исследуйте», «Обратите внимание», «Вернёмся»), без «мы видели», без форм «мы делаем» («делим», «переводим», «Определим»).
- В пояснениях и решениях только безличная форма: «Определяется время встречи», а не «Определим время встречи».
- Повелительное наклонение только в формулировках заданий: «Определите время движения и приобретённую скорость».

### 2.4. Без риторических вопросов

Проблема формулируется утвердительно. Вопрос остаётся в заданиях и в формулировке проблемы занятия.

### 2.5. Технические объекты не очеловечиваются

«Компьютеры возвращаются к своим хозяевам» → нейтральное описание в терминах предмета.

### 2.6. Полные фразы

Фраза с подлежащим и сказуемым, без рубленых пометок: «Время не дано и не нужно» → «Время движения не задано и не требуется».

## 3. Терминология и лексика

### 3.1. Бытовые слова заменяются терминами предмета

| Было | Стало |
|---|---|
| развернулось | изменило направление движения |
| стоит, не едет назад | остаётся в покое |
| ехал | двигался |
| растёт | возрастает |
| загибается вверх | ветви направлены вверх |
| выполаживается | угол наклона уменьшается |
| ускорения нет | ускорение равно нулю |
| Что нужно найти | Искомая величина |
| проверка на смысл | проверка правдоподобности ответа |
| откуда петли | чем объясняется попятное движение |
| звёзды очень далеко | звёзды очень удалены |
| заметает | описывает |
| хозяин (компьютера) | владелец |
| визит | удалённый сеанс |
| записка, отметка | информационный файл, регистрационный файл |

### 3.2. Точность в терминах величин

- «Проекция перемещения», «проекция ускорения», где речь о проекции.
- «Ускорение 3 м/с² (по модулю)» → «ускорение, модуль которого 3 м/с²».
- «Площадь численно равна проекции перемещения».

### 3.3. Без образной лексики

Без слов вроде «козырь», «разбавить», «несётся», «незачем», «смущал», «ловушка» и без кавычек «для образности».

### 3.4. Синонимы терминов

Термин выбирается по справочным изданиям. При первом упоминании синоним даётся в скобках: «попятное движение (ретроградное движение; англ. retrograde motion)».

### 3.5. Реалии и примеры

- Без иллюстраций на примере России: школа в Черногории, ученики из разных стран. Общие формулировки, европейские и международные ориентиры (GDPR, Бернская конвенция, Europeana, Coursera).
- Предметные реалии соответствуют реальной среде класса. Например, команды и пути в курсе информатики — для Debian 13, а не для Ubuntu.

## 4. Заголовки и надписи

### 4.1. Заголовки назывные

- Отглагольное существительное, без «мы делаем», вопросов и призывов. Несколько действий через точку: «Повторяем кинематику и решаем задачи» → «Повторение кинематики. Решение задач»; «Исследуйте модель» → «Модель: фазы Венеры»; «Модель или реальность?» → «Статус модели».
- Повторяющиеся блоки называются одинаково: «Модель: …», «Основной кейс: …», «Вывод», «Основной тезис занятия», «Цель занятия».

### 4.2. Единые подписи кнопок

- Модели: «Запустить» / «Пауза», «Сначала», «На весь экран» / «Обычный режим».
- Восстановление сессии: «Начать заново» и «Продолжить».

### 4.3. Форма входа в тренажёр

- Поля «Имя» и «Фамилия» обычного размера, без поля «Класс».
- Неприметная серая кнопка «Пройти анонимно»; аноним получает код вида «Аноним A-8C9F03».
- Под полями одна неброская строка: не закрывать окно до конца теста.

## 5. Задания, тренажёры, сообщения проверки

### 5.1. Формулировка вопроса однозначна

Если вопрос про код, код приводится в самом вопросе. У функций в заданиях на порядок действий есть краткое описание того, что функция делает.

### 5.2. Ответ нельзя угадать по форме

- Правильный вариант не самый длинный.
- Неверные варианты правдоподобны (соседние понятия, частые заблуждения), не нелепы и не шутливы.
- Верные варианты не стоят первыми подряд: порядок вариантов перемешивается детерминированно (зерно — идентификатор вопроса), чтобы он был одинаковым после перезагрузки и у всех учеников.
- В заданиях на соответствие ключевые слова ответа не повторяются в вопросе.

### 5.3. Вопросы общие, через ситуацию

Без частностей (годы документов, названия конкретных платформ). Лучше ситуация, из которой ответ выводится.

### 5.4. Варианты ответа — утверждения

Без разговорного «Потому что…».

### 5.5. Типы заданий в тренажёре

- Тренажёр служит запоминанию, а не контролю.
- Подходящие типы: перетаскивание фрагментов в пропуски (или выбор щелчком) с подсказкой в каждом пропуске, порядок строк, сопоставление, поиск пар, набор команды по описанию, практикум со свободной правкой заготовки или во встроенном терминале.
- Ввод кода или команды разрешён, если проверка не зависит от пробелов и регистра или идёт по поведению программы.

### 5.6. Структура блока тренажёра

Сначала теория с примерами и объяснением, затем короткая проверка. Задания исходят из чистого компьютера: сначала создать файлы, потом работать с ними; подготовительные шаги ученик выполняет сам по инструкции.

### 5.7. Сообщения проверки краткие и нейтральные

«Верно», «Неверно», «Неверно определены: … Обратите внимание на знак ускорения на участке III». Не «Пока нет».

### 5.8. Описание тренажёра нейтральное

«Тренажёр состоит из коротких заданий; результаты не сохраняются и не оцениваются».

### 5.9. Цели занятия

Инфинитив и отглагольные существительные: «Закрепить выбор формулы… учёт знаков проекций».

### 5.10. Задания для самопроверки в конспекте

В конце новой темы несколько заданий, у каждого скрывающаяся плашка «Проверить себя» с ответом и коротким решением. Это не работа на оценку и не тренажёр.

### 5.11. Сомнительное условие

Сначала проверяется. Меняется только по решению автора курса.

## 6. Типографика и формулы

### 6.1. Неразрывные пробелы

- Обязательно между числом и единицей (5 м/с, 72 км/ч, 10 мин) везде: в тексте, условиях, вариантах, тренажёрах, решениях, сообщениях проверки.
- Желательно между числом и существительным: «2 урока», «в 4 раза».

### 6.2. Формула не разрывается переносом

- Формула, выражение, адрес, код целиком на одной строке (`white-space: nowrap` или неразрывные пробелы). Длинная формула выносится отдельной строкой.
- Если формула шире экрана телефона, она разбивается по знакам «=» на строки.

### 6.3. Индексы

- Величина курсивом, индекс прямым, вплотную: `<i>v</i><sub>0x</sub>`.
- Нельзя ставить индекс внутри курсива и использовать символы Юникода вида «vₓ».
- В SVG индекс — отдельный `<tspan>` со сдвигом и меньшим кеглем.
- Внутри flex/grid (варианты ответа, кнопки, карточки) текст с формулой лежит в одной обёртке `<span>`, чтобы индекс и запятая не отрывались.

### 6.4. Несколько равенств в строке

После запятой отступ около 1 em: «6*t* = 30,  *t* = 5 с».

### 6.5. Пошаговые выкладки

Левая часть прижата к «=», перед «=» небольшой отступ, без широкой колонки.

### 6.6. Порядок записи

Левая часть, «=», правая часть, в том числе в тренажёрах на пары.

### 6.7. Дроби

- Формулы набираются с горизонтальной дробной чертой средствами CSS, без внешних математических библиотек (файл автономный), в том числе в подписях на графиках.
- Простая дробь в строке текста и в сообщениях проверки может быть записана через косую черту: «aₓ/2».

### 6.8. Кавычки, тире, ё

Кавычки «ёлочки», длинное тире (—) между частями предложения, буква ё.

## 7. Бумажные листы (работы и обратная связь)

### 7.1. Объём

Лист ученика помещается на одной стороне A4. Допустимы две колонки, условия компактнее.

### 7.2. Место для решения

- Под каждым заданием бледно-серая клетка 5 мм, объём по сложности (примерно 20–80 мм).
- В шапке «Баллы … из …» и «Оценка».
- Формат PDF предпочтительнее DOCX.

### 7.3. Служебное только у учителя

- Номера листов скана, «Требует ручной проверки» и подобные пометки — только на листе учителя в начале файла. У ученика такая фраза удаляется целиком.
- Первый лист для учителя содержит общую характеристику работы.

### 7.4. Обратная связь ученику

- Порядок: вверху оценка, затем ошибки, затем работа над ошибками.
- По умолчанию только перечень ошибок, без анализа. В алгебре — ошибки с кратким анализом и перечнем верных решений.

### 7.5. Работа над ошибками

- Задания по аналогии с нерешёнными; одна задача на тему, без повторов.
- Сильным ученикам одно-два задания повышенной сложности или со звёздочкой; лист рассчитан примерно на 20 минут.
- Лист готовится и для тех, кто работу не писал.

### 7.6. Оцифровка работ учеников

Близко к оригиналу, ошибки сохраняются. Markdown + LaTeX, строка листа = строка файла, пометки ⟦зачёркнуто⟧, ⟦неразборчиво⟧, ⟨?⟩.
