# Спецификация учебной HTML-страницы (Learn-it 4.3)

## 1. Статус

Спецификация пакета **Learn-it 4.3**. Визуальная система, геометрия, адаптивность и доступность сохранены с v1.5. В 4.1 добавлены правила вёрстки текста: две колонки на широком экране, выравнивание по ширине, ограничения ширины таблиц и графиков, запрет горизонтальной прокрутки на телефоне, типографика формул. Подробно они изложены в [STYLE_GUIDE.md](STYLE_GUIDE.md), там же правила языка, заголовков и заданий. В 4.2 добавлены двухколоночная раскладка заданий, правило начисления баллов в оцениваемых работах (п. 31.5), блок «План занятия» и требования к рисункам приборов. В 4.3 добавлены метаданные `catalog:number`, `catalog:parent`, `catalog:nav` для новой структуры каталога и строки пути (см. [NAVIGATION_SPEC.md](../03-catalog/NAVIGATION_SPEC.md)).

Она сохраняет:
- метаданные каталога;
- базовую цветовую систему;
- максимальную desktop-ширину и compact desktop;
- семантику `radio` / `checkbox`;
- визуальные состояния выбора, успеха и ошибки;
- мобильную компоновку;
- поддержку `prefers-reduced-motion`;
- локальное сохранение файлов, создаваемых учеником.

Геометрическое правило остаётся неизменным:

> Размеры элементов учебной страницы не должны увеличиваться вместе с шириной viewport. На широком экране увеличиваются прежде всего боковые поля, а не шрифты, кнопки и карточки.

Актуальные положения:

- `catalog:hidden` и `catalog:legacy` поддерживаются генератором каталога;
- Legacy-файл не создаёт отдельную строку каталога;
- рекомендуемое имя Legacy-файла — `<основное_имя>_Legacy.html`;
- основной каталог курса генерируется как готовый HTML и работает без обязательного JavaScript;
- файлы, создаваемые учеником, сохраняются локально в базовой архитектуре; копия учителю, если нужна, отправляется событием `result_submitted`;
- тренажёры могут отправлять события в работающий Telemetry API на Yandex Cloud;
- базовая единица прохождения — `attemptId`, события упорядочиваются полем `seq`;
- недоступность telemetry backend не должна блокировать основную учебную механику.

# 2. Область действия

Спецификация определяет:
- техническую реализацию HTML-материала;
- базовую визуальную систему;
- геометрию страницы;
- адаптивное поведение;
- размеры основных элементов интерфейса;
- требования к интерактивности и доступности;
- метаданные каталога.

Она **не определяет**:
- педагогическую структуру материала;
- обязательный набор разделов;
- тип учебной активности;
- необходимость теста, тренажёра, таблицы, навигации или иных компонентов;
- содержание урока.

Наличие компонента в примере не означает, что такой компонент должен присутствовать в новом материале.

# 3. Обязательные технические требования

В `<head>`:

```html
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
```

Страница должна:
- работать в современных браузерах;
- поддерживать масштабирование браузером;
- не запрещать zoom;
- не требовать фиксированного физического разрешения;
- корректно работать при системном масштабировании Windows/macOS;
- иметь мобильную компоновку.

Не допускается:

```html
user-scalable=no
maximum-scale=1
```

# 4. Метаданные каталога

Полный набор:

```html
<meta name="catalog:title" content="">
<meta name="catalog:type" content="">
<meta name="catalog:topic" content="">
<meta name="catalog:description" content="">
<meta name="catalog:tags" content="">
<meta name="catalog:order" content="">
<meta name="catalog:hidden" content="">
<meta name="catalog:legacy" content="">
<meta name="catalog:number" content="">
<meta name="catalog:parent" content="">
<meta name="catalog:nav" content="">
```

Обязательные поля:

```text
catalog:title
catalog:type
```

Необязательные:

```text
catalog:topic
catalog:description
catalog:tags
catalog:order
catalog:hidden
catalog:legacy
catalog:number
catalog:parent
catalog:nav
```

## `catalog:title`

Название в каталоге.

```html
<meta name="catalog:title" content="Название материала">
```

HTML-тег `<title>` не используется как источник названия каталога.

## `catalog:type`

Тип материала.

```html
<meta name="catalog:type" content="lesson">
```

Список типов открыт:

```text
lesson
test
trainer
game
reference
lab
exam
cheatsheet
presentation
...
```

## `catalog:order`

При необходимости задаёт порядок:

```html
<meta name="catalog:order" content="20">
```

Меньшее число располагается выше.

С 4.3 `catalog:order` не влияет на порядок конспектов (`catalog:type=lesson`): их порядок задаёт порядковый номер. Поле упорядочивает общие материалы и материалы внутри строки конспекта (см. [NAVIGATION_SPEC.md](../03-catalog/NAVIGATION_SPEC.md), 5.4).

## `catalog:number`

Только для конспекта (`catalog:type=lesson`). Явно задаёт порядковый номер конспекта в каталоге курса:

```html
<meta name="catalog:number" content="7">
```

Обычно не нужен: номер присваивается автоматически при первой публикации и сохраняется в `catalog.json`. Используется для перехода существующих курсов и для промежуточного номера вида `7а`. Номер не должен повторяться внутри курса. Подробно — [NAVIGATION_SPEC.md](../03-catalog/NAVIGATION_SPEC.md), раздел 4.

## `catalog:parent`

Для материала к конспекту (тренажёр, анимация, заметка и т. п.). Путь к файлу конспекта относительно самого материала:

```html
<meta name="catalog:parent" content="algebra_11_unit_circle_lesson.html">
```

Без этого поля материал привязывается к конспекту из той же папки. Поле нужно, если материал лежит не в папке своего конспекта. Пустое значение делает материал общим. Подробно — [NAVIGATION_SPEC.md](../03-catalog/NAVIGATION_SPEC.md), 3.5.

## `catalog:nav`

```html
<meta name="catalog:nav" content="off">
```

`off` — сборка не вставляет в материал строку пути «learn-it.app › курс › номер». Для полноэкранных анимаций и игр. По умолчанию строка вставляется.

## `catalog:hidden`

```html
<meta name="catalog:hidden" content="true">
```

`true`:
- файл остаётся опубликованным;
- прямая ссылка работает;
- материал не показывается в каталоге.


## `catalog:legacy`

Необязательная ссылка на альтернативную версию материала для устаревшего браузера.

```html
<meta name="catalog:legacy" content="density_Legacy.html">
```

Правила:

- путь задаётся относительно основного HTML-файла;
- абсолютные URL и выход выше корня курса через `../` не допускаются;
- генератор проверяет фактическое наличие указанного файла;
- отсутствие тега и пустое значение эквивалентны;
- при отсутствии legacy-версии генератор каталога должен использовать `legacy: null`;
- legacy-версия не должна создавать отдельную строку каталога;
- legacy-файл рекомендуется помечать `catalog:hidden=true`.

Пример:

```html
<!-- основной материал -->
<meta name="catalog:title" content="Плотность вещества">
<meta name="catalog:type" content="lesson">
<meta name="catalog:legacy" content="density_Legacy.html">
```

```html
<!-- density_Legacy.html -->
<meta name="catalog:hidden" content="true">
```

Каталог должен отображать legacy-ссылку рядом с основной ссылкой того же материала.

# 5. Базовая цветовая система

```css
:root {
  --green: #123d32;
  --green2: #1d5a49;

  --paper: #ffffff;
  --bg: #edf2ee;

  --ink: #14201c;
  --muted: #61716b;

  --accent: #ffb000;

  --ok: #238b57;
  --bad: #c8413a;

  --line: #d7e0dc;
}
```

Назначение:
- `--green` — header, основные действия, ключевые заголовки;
- `--green2` — hover, вторичные зелёные элементы;
- `--paper` — рабочие поверхности;
- `--bg` — фон страницы;
- `--ink` — основной текст;
- `--muted` — вторичный текст;
- `--accent` — выбор, прогресс, focus;
- `--ok` — правильный результат;
- `--bad` — ошибка;
- `--line` — границы и разделители.

# 7. Основной принцип геометрии v1.3

## 7.1. CSS viewport важнее физического разрешения

Физическое разрешение монитора не равно размеру viewport в CSS-пикселях.

Пример:

```text
2560 × 1440
Windows scaling 200%
≈
1280 × 720 CSS px
```

Поэтому адаптивность определяется по **CSS viewport**, а не по физическому разрешению дисплея.

---

# 8. Обычный desktop

Для viewport шире `1400 CSS px`:

```css
:root {
  --material-max: 1120px;
}

.wrap,
main {
  width: min(var(--material-max), calc(100% - 40px));
  margin-inline: auto;
}
```

Основной контент:
- не шире `1120px`;
- центрирован;
- имеет минимум около `20px` внешнего поля на небольшом desktop;
- на 2K / 4K не увеличивается;
- дополнительная ширина экрана превращается в боковые поля.

Главное правило:

```text
шире экран → больше боковые поля
НЕ
шире экран → крупнее интерфейс
```

---

# 9. Compact desktop

Для:

```text
721–1400 CSS px
```

используется отдельный режим.

Базовая геометрия:

```css
@media (max-width: 1400px) and (min-width: 721px) {
  .wrap,
  main {
    width: min(900px, calc(100% - 36px));
    margin-inline: auto;
  }
}
```

Этот режим предназначен в том числе для:
- high-DPI экранов;
- Windows scaling 150–200%;
- ноутбуков с небольшим логическим viewport;
- 2560×1440 при 200% масштабировании системы.

# 10. Header

Header учебного материала — служебный блок, а не hero-screen.

Он не должен занимать значительную часть первого экрана.

## Обычный desktop

Рекомендуемые значения:

```text
padding сверху/снизу: около 18 / 16 px
h1: около 30 px
eyebrow: около 11 px
lead / subtitle: около 14 px
badge: около 11 px
```

## Compact desktop

```text
padding сверху/снизу: около 11 / 10 px
h1: около 24 px
eyebrow: около 9–10 px
lead: около 12 px
badge: около 10 px
```

Не рекомендуется использовать для основного заголовка:

```css
font-size: clamp(...vw...);
```

если это приводит к заметному увеличению заголовка на широких экранах.

# 11. Навигация

Если у материала есть внутренняя навигация, она должна быть компактной.

Обычный desktop:

```text
размер текста: около 12 px
вертикальные отступы ссылки: около 7 px
```

Compact desktop:

```text
размер текста: около 10.5–11 px
вертикальные отступы: около 5 px
```

Допускается sticky-навигация.

Пункты навигации короткие и помещаются в одну строку («ДЗ», а не «Домашнее задание»). Первый пункт меню конспекта занятия — «План занятия» (см. [STYLE_GUIDE.md](STYLE_GUIDE.md), 1.11). На узком экране навигация переносится на вторую строку или сворачивается, но не создаёт горизонтальную прокрутку страницы.

Крупные части занятия (теория, тренировка, практикум) оформляются отдельными переключаемыми страницами внутри одного HTML-файла. Из любого раздела в любой другой переход в один щелчок: меню в шапке и кнопки «Назад» / «Далее» внизу раздела (см. [STYLE_GUIDE.md](STYLE_GUIDE.md), раздел 1.9).

Над шапкой материала сборка вставляет строку пути «learn-it.app › курс › номер» ([NAVIGATION_SPEC.md](../03-catalog/NAVIGATION_SPEC.md), 6.2). Добавлять ссылку «в каталог» вручную не нужно. Собственная sticky-навигация материала не должна перекрывать эту строку при открытии страницы.

# 12. Основной текст

## Обычный desktop

```text
body: 16 px
line-height: примерно 1.45–1.5

h1: ~30 px
h2: ~22 px
h3: ~17 px
```

## Compact desktop

```text
body: 14 px
line-height: примерно 1.42–1.45

h1: ~24 px
h2: ~18 px
h3: ~15 px
```

## Mobile

Основной текст возвращается к:

```text
16 px или больше
```

для комфортного чтения.

## Вёрстка текста

- На desktop и compact desktop основной текст набирается в две колонки; на mobile в одну.
- Одиночный абзац между блоками ставится в узкую колонку около `680px`.
- Крупные блоки текста выравниваются по ширине, красная строка `1.5em`, `hyphens: auto` (у `<html>` указан `lang="ru"`). Короткие подписи, панели, таблицы — по левому краю. На mobile текст выравнивается по левому краю, красная строка сохраняется.
- Футер не ставится.

```css
.prose { column-count: 2; column-gap: 28px; }
.prose p { text-align: justify; text-indent: 1.5em; hyphens: auto; }
.prose-narrow { max-width: 680px; }

@media (max-width: 720px) {
  .prose { column-count: 1; }
  .prose p { text-align: left; }
}
```

Подробности и примеры: [STYLE_GUIDE.md](STYLE_GUIDE.md), раздел 1.

# 13. Карточки и рабочие поверхности

Карточки не должны выглядеть как крупные презентационные блоки.

Обычный desktop:

```text
padding: около 20 px
margin-bottom: около 12 px
border-radius: около 10 px
```

Compact desktop:

```text
padding: около 14 px
margin-bottom: около 9 px
border-radius: около 8 px
```

Рекомендуется:
- тонкая граница;
- очень лёгкая тень или отсутствие тени;
- умеренное скругление;
- отсутствие лишних декоративных отступов.

# 14. Сетки

На desktop допускаются:
- 2 колонки;
- 3 колонки;
- асимметричные схемы для текста + иллюстрации;
- специальные колонки тренажёра;
- двухколоночная раскладка задания: рисунок или список ответов слева, элементы ответа справа (подробно: [STYLE_GUIDE.md](STYLE_GUIDE.md), 1.2).

Пример:

```css
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
```

Парные блоки (определение и формула, алгоритм и типичная ошибка, термин и пояснение) ставятся рядом в две колонки.

На mobile многоколоночная структура перестраивается в одну колонку.

Compact desktop не обязан переходить в mobile-компоновку: вместо этого уменьшаются ширина контента и размеры интерфейса.

---

# 15. Таблицы

Обычный desktop:

```text
примерно 14 px
```

Compact desktop:

```text
примерно 12–13 px
```

Ширина таблицы ограничена: около `920px`. Код в ячейке не переносится посреди конструкции, вместо этого колонка шире.

При недостатке ширины таблица должна:
- либо корректно перестраиваться (предпочтительно);
- либо, если это широкая таблица данных, иметь собственный горизонтальный scroll-контейнер. Сама страница горизонтально не прокручивается.

Текст таблицы не должен увеличиваться вместе с viewport.

---

# 16. Формулы и специальные блоки

Формула или важная информационная строка не должна становиться огромным декоративным элементом.

Обычный desktop:

```text
примерно 16 px
padding: около 9–12 px
```

Compact desktop:

```text
примерно 14 px
padding: около 7–9 px
```

Набор формул:
- формула, выражение, адрес, код не разрываются переносом (`white-space: nowrap` или неразрывные пробелы); длинная формула выносится отдельной строкой, а если она шире экрана телефона — разбивается по знакам «=»;
- величина курсивом, индекс прямым: `<i>v</i><sub>0x</sub>`; без индексов внутри курсива и символов Юникода вида «vₓ»;
- дроби в формулах — с горизонтальной чертой средствами CSS, без внешних математических библиотек; в строке текста допустима косая черта;
- между числом и единицей неразрывный пробел.

Графики: на desktop не шире примерно `560px`, на mobile во всю ширину.

Подробности: [STYLE_GUIDE.md](STYLE_GUIDE.md), раздел 6.

На compact desktop:

# 18. Hover

Основная кнопка:

```css
.primary {
  background: var(--green);
  color: white;
}

.primary:hover {
  background: var(--green2);
}
```

Акцентная:

```css
.accent {
  background: var(--accent);
  color: #281b00;
}

.accent:hover {
  background: #e9a200;
}
```

Вторичная:

```css
.secondary {
  background: white;
  color: var(--green);
  border: 1px solid var(--line);
}

.secondary:hover {
  background: #eaf4ef;
  border-color: #aec7bd;
}
```

---

# 19. Focus

Клавиатурный focus должен быть видимым.

```css
button:focus-visible,
a:focus-visible,
input:focus-visible,
select:focus-visible {
  outline: 3px solid var(--accent);
  outline-offset: 2px;
}
```

Не следует показывать крупную focus-рамку после обычного клика мышью, если браузер корректно поддерживает `:focus-visible`.

# 20. Одиночный выбор

Если уже выбрана механика классического одиночного ответа, использовать:

```html
<input type="radio">
<label for="...">...</label>
```

Пример:

```html
<fieldset class="choice-list">
```

# 23. Состояния выбора и проверки

Выбор:

```css
.choice-option input:checked + .choice {
  border-color: #d19a00;
  background: #fff3cf;
}
```

Правильный ответ:

```css
.correct {
  border-color: var(--ok);
  background: #e5f6ed;
}
```

Неверный:

```css
.wrong {
  border-color: var(--bad);
  background: #fff0ef;
}
```

# 24. Mobile

До `720 CSS px`:

```css
@media (max-width: 720px) {
  .wrap,
  main {
    width: calc(100% - 28px);
    margin-inline: auto;
  }
}
```

Рекомендуется:
- боковые поля около `14px`;
- одна колонка;
- основной текст `16px+`;
- h1 около `24px`;
- h2 около `20px`;
- touch target `44px+`;
- никакой горизонтальной прокрутки страницы: длинная выкладка разбивается на строки или список;
- двухколоночные задания перестраиваются в одну колонку; рисунок задания не шире 240 px и выровнен по центру, широкий рисунок (линейка) во всю ширину.

Mobile не должен наследовать уменьшенный `14px` body из compact desktop.

# 25. Масштабирование

Не использовать viewport как источник постоянного увеличения интерфейса.

Нежелательная модель:

```css
h1 {
  font-size: clamp(30px, 5vw, 58px);
}
```

если из-за неё на широком дисплее заголовок становится значительно крупнее.

Предпочтительно:

```css
h1 {
  font-size: 30px;
}

@media (max-width: 1400px) and (min-width: 721px) {
  h1 {
    font-size: 24px;
  }
}
```

# 30. Файлы, создаваемые учеником

Некоторые тренажёры формируют текст, исходный код, JSON, изображения или другие результаты работы.

Базовое правило:

> такой файл сохраняется локально на устройстве ученика средствами браузера.

Если учитель должен получить результат, страница дополнительно отправляет его событием `result_submitted` через `cloudSubmit` (см. [RESULTS_AND_FILES_ARCHITECTURE.md](../01-architecture/RESULTS_AND_FILES_ARCHITECTURE.md), раздел 2a). Netlify Forms не используются. Локальное сохранение остаётся обязательным запасным путём.

Это отделяет публикацию учебных материалов от пользовательского upload. Если централизованный приём файлов понадобится позже, он проектируется как отдельная подсистема с собственным API, хранилищем и правилами доступа.

HTML-материал не должен содержать секретные ключи облачного хранилища, YDB или сервисного аккаунта.

# 31. Результаты и события тренажёров

Для тренажёров используется отдельный Telemetry API.

Текущая схема:

```text
HTML на learn-it.app (Yandex Object Storage)
→ HTTPS POST /api/v1/events
→ Yandex API Gateway
→ Cloud Function
→ YDB events
```

Клиентская спецификация не зависит от внутренней облачной реализации. Нормативный контракт описан в [TRAINER_TELEMETRY_SPEC.md](../05-telemetry/TRAINER_TELEMETRY_SPEC.md).

## 31.1. Попытка

Каждое новое прохождение создаёт новый `attemptId`.

События внутри попытки получают `seq`:

```text
1, 2, 3, ...
```

Один и тот же `attemptId` используется для всего прохождения.

## 31.2. Событие

Базовые обязательные поля события:

```text
seq
eventType
eventVersion
schemaVersion
clientTime
elapsedMs
trainerId
trainerVersion
eventSource
context
data
```

Пример:

```json
{
  "seq": 12,
  "eventType": "answer_changed",
  "eventVersion": 1,
  "schemaVersion": 1,
  "clientTime": "2026-09-27T16:50:00.000Z",
  "elapsedMs": 84251,
  "trainerId": "physics-7-pressure-lesson-2026-09-28",
  "trainerVersion": "1.0.0",
  "eventSource": "user",
  "context": {
    "pageId": "page-2",
    "questionId": "q5"
  },
  "data": {}
}
```

`context` и `data` могут расширяться под механику конкретного тренажёра.

## 31.3. Доставка

События сначала добавляются в локальную очередь и удаляются из неё только после успешного ответа `HTTP 200` с `ok=true`.

Повторная отправка того же `(attemptId, seq)` допустима: серверное хранилище использует идемпотентный ключ.

Техническая ошибка отправки не должна выглядеть как учебная ошибка и не должна блокировать основную работу тренажёра.

## 31.4. Сырые события

Сырой event log является источником истины. Сам тренажёр не должен вычислять оценочные показатели поведения наподобие `cheating score` или `suspicion score`.

# 32. Legacy browser support

Современная версия материала является основной. При необходимости рядом создаётся технически облегчённая альтернативная версия.

Рекомендуемая схема:

```text
material.html
material_Legacy.html
```

Основной файл:

```html
<meta name="catalog:legacy" content="material_Legacy.html">
```

Legacy-файл:

```html
<meta name="catalog:hidden" content="true">
```

Безопасный относительный путь в подпапку также допустим, но рекомендуемое соглашение для новых материалов — суффикс `_Legacy`.

Генератор каталога:

- проверяет, что путь не является абсолютным;
- не допускает выход выше корня курса через `../`;
- проверяет существование файла;
- добавляет Legacy-ссылку только при успешной проверке.

Главное правило:

```text
один учебный материал = одна строка каталога
```

Legacy-ссылка отображается в строке основного материала как `HTML | lite` и остаётся обычным `<a href>` с текстовым fallback.

Подробные правила: [LEGACY_BROWSER_SUPPORT.md](../03-catalog/LEGACY_BROWSER_SUPPORT.md).

## 31.5. Баллы в оцениваемых работах

- Сопоставление: каждая верная пара — 1 балл.
- Выбор нескольких ответов: каждая верная отметка +1 балл, каждая лишняя отметка −1 балл; за задание не меньше 0. Максимум за задание равен числу верных вариантов.
- Страницу можно проверить не более 3 раз. Баллы, полученные при первой проверке, засчитываются полностью; прибавка, полученная после второй проверки, — с коэффициентом 0,5; после третьей — 0,25. В задании с выбором засчитывается только прирост результата (верные − лишние) по сравнению с лучшим предыдущим, поэтому сначала отметить всё, а потом убрать лишнее невыгодно.
- Правило показывается ученику перед работой в блоке «Оценивание».
- Сообщение проверки задания с выбором: «Верных отметок: 2 из 3, лишних: 1. Засчитано: 1 из 3 б.»
- Каждая проверка отправляется событием `answers_checked`, итог по элементам содержит `checks`, `points`, `maxPoints` ([TRAINER_TELEMETRY_SPEC.md](../05-telemetry/TRAINER_TELEMETRY_SPEC.md), разделы 11 и 25).
