# Как создавать конспект К<N> (правила для агента и для учителя)

Курс «Информатика 8. Алгоритмы + Python». Файл заменяет повторное чтение `ЗАДАНИЕ.md`, `spec/`, `learn-it-4.3-docs/`: здесь собрано всё нужное. Полные тексты читать только при споре (приоритет: вёрстка и язык — Learn-it, телеметрия и доступ — `spec/specifikaciya-konspekta.md`).

## 0. Экономия токенов (обязательно)

- **Никогда не открывать собранные `K<N>/*.html` и `vendor/`**: в них около 1 МБ Skulpt. Править только `lessons/K<N>/` и `engine/`.
- Новый урок начинать копированием ближайшего готового: `cp -r lessons/K2 lessons/K5`, затем заменить содержание. Читать только его `lesson.json`, `data.js`, `pages.html`.
- Образец рисунка turtle и ожидаемые отрезки получать запуском `node tools/trace.js решение.py`, а не вручную.
- После правки: `node tools/build.js K<N>` и `node tools/verify.js K<N>`. Скриншоты смотреть только при правке вёрстки.

## 1. Структура репозитория

```text
course.json              общие настройки курса (адрес Apps Script и адрес сайта курса заданы)
engine/                  движок и оформление (общие для всех уроков; менять только по решению учителя)
  shell.html css/ js/    оболочка, стили, скрипты (вход, песочница, телеметрия, восстановление)
  turtle_trace.py        замена turtle для автопроверки рисунка
lessons/K<N>/            содержание урока (только это пишется для нового урока)
  lesson.json            название, меню частей, метатеги каталога, id задач практикума
  pages.html             разметка частей конспекта
  data.js                задачи (TASKS) и вопросы (QUESTIONS)
  solutions.json         эталонные решения и типичные неверные решения (для verify.js)
  methodichka.md         методичка учителя
tools/                   build.js, verify.js, trace.js, тесты скрипта (gas_test.js)
K<N>/                    результат сборки: K<N>_<slug>.html и LOCAL_metodichka_K<N>.md (коммитится)
apps-script/             Code.gs и README.md: один скрипт на весь курс (в папки уроков не кладётся)
```

`catalog:title` — без «Занятие N». Метатеги и Skulpt добавляет сборка. Строку пути и счётчик Метрики вставляет сборка сайта Learn-it, вручную не добавлять.

## 2. Части конспекта (спецификация, табл. 1.1)

| Часть (`data-part`) | Время | Содержание |
|---|---|---|
| `plan` План занятия | — | Тема, «Цель занятия» (инфинитив), список частей с временем, «Планируемый результат» (узкий блок). Одна колонка, без «Перемены». Для К2+ ссылка на предыдущий конспект: `../K<N-1>/<файл>.html` |
| `review` Повторение | 3 мин | 2–3 вопроса по прошлой теме, мгновенная проверка (режим `instant`); обычно «Что выведет программа?» |
| `theory` Теория | 7 мин | 2–3 шага: пояснение (2–3 абзаца, `.prose`) → блок-схема и тот же алгоритм на Python рядом (`.fig-pair`) → песочница без проверки (`kind: 'free'`). Порядок: предсказать, запустить, сравнить |
| `code` Разбор кода | 5 мин | Готовая программа и три задания: «Определите, что выведет программа» (вопрос, режим `check`), «Измените одно значение», «Найдите и исправьте ошибку» (задачи `check`) |
| `practice` Практикум | 15–18 мин | 3 обязательные задачи + 2 со звёздочкой (★), по возрастанию сложности (`p1`…`p5`) |
| `summary` Итог | 3 мин | «Вывод» (годится для печати), 2–3 задания «Проверить себя» (режим `reveal`), кнопки итога (уже в `pages.html` К1: копировать блок `finish-box`) |

Пункт «ДЗ» (`hw`) добавляется в `lesson.json → parts` и в `pages.html`, только если есть домашнее задание. Печать выводит `plan`, `theory`, `summary` (классы `print-page` на `section`, `noprint` на лишнем).

## 3. Что можно использовать в Python по урокам

Конструкция вводится в уроке из названия темы и позже; **раньше — нельзя** (ни в тексте, ни в заданиях, ни в эталонах).

| Урок | Допустимо (накопительно) |
|---|---|
| К1 | `print("текст")`, `print()` |
| К2 | + комментарии `#`; чтение сообщений об ошибках; блок-схемы (овал, прямоугольник, параллелограмм; ромб только как обозначение) |
| К3 | + модуль `turtle` в функциональном виде: `import turtle`, `turtle.forward/backward/left/right/penup/pendown/pencolor/pensize/goto`; без переменных и циклов. Пятничная группа К3 пропускает |
| К4 | + переменные, присваивание, `str`/`int` |
| К5 | + `input()`, типы данных, `print` с несколькими аргументами |
| К6–К7 | + арифметика `+ - * / ** // %` |
| К8–К14 | + `if/else`, логика, `elif`, `and/or/not`, сравнения |
| К15–К19 | + `for`, `range`, счётчик и сумма, `while`, `break` |
| К15 | блок «Исполнитель „Черепаха“: краткое введение» для пятничной группы (раскрывающийся `<details>`) |

Названия тем К1–К20 — `spec/raspisanie-po-nedelyam.xlsx`, лист «Конспекты». Если у группы «практикум/резерв» вместо темы, конспект тот же.

## 4. Язык и оформление (выжимка STYLE_GUIDE)

- Академический, но простой язык; фразы короткие и полные. **Пояснения безличные**: «Определяется…», «Переменной присваивается…». Нельзя: «ты», «вы», «мы», «давайте», призывы, восклицания, риторические вопросы. Повелительное наклонение только в заданиях: «Напишите программу…».
- Заголовки назывные («Повторение кода», «Вывод», «Цель занятия»). Цели — инфинитивом.
- Термины по учебнику Босовой; синоним или английский термин при первом упоминании в скобках: «исполнитель (англ. *executor*)». Без образной лексики и бытовых слов вместо терминов.
- Примеры без привязки к России: школа в Черногории — евро, километры, Подгорица, Котор, Будва, Бар, Адриатическое море, международные реалии.
- Типографика: «ёлочки», длинное тире «—», буква «ё», неразрывный пробел между числом и единицей (`&nbsp;`: `60&nbsp;км`). В тексте для вывода программ тире и ё **не требовать** (ученик не наберёт «—»): в ожидаемом выводе дефис и обычные пробелы. Код и формулы не переносятся.
- Вёрстка: два столбца текста на компьютере (`.prose`), одиночный абзац ≤ 680 px (`.lede`), парные блоки в две колонки (`.grid2`, `.fig-pair`), таблицы ≤ 920 px с `class="tbl stack"` и `data-l` в ячейках, блок-схемы только через `data-flow` (SVG строится программно, не шире 560 px), без футера, без «Терминов занятия» и «Следующего занятия».
- Сообщения проверки краткие и нейтральные («Верно», «Неверно: …»). Пояснения к ошибкам безличные.
- Варианты ответа: верный не самый длинный и не первый (порядок перемешивается детерминированно), неверные правдоподобны, без шуток. Вопросы общие, через ситуацию.
- Задачи посильны тем, кто программирует впервые. Баллов за задачи нет.

## 5. Формат содержания

### lesson.json
Как в `lessons/K1/lesson.json`: `id`, `title`, `lessonTitle` («К2 …»), `outName` (латиницей), `eyebrow`, `lead`, `badges`, `trainerId` (`informatics-8-k02-lesson`), `catalog.{topic,description,tags}`, `practiceTaskIds`, `parts`.

### pages.html
Секции `<section class="page" id="page-<часть>" data-part="<часть>" aria-labelledby="h-<часть>">` с заголовком `<h2 id="h-<часть>" tabindex="-1">`. Песочница и задача вставляются так: `<div class="sbx" data-task="p1"></div>` (содержимое строится из `TASKS.p1`). Вопросы: `<div class="qs" data-qgroup="review"></div>` (все вопросы группы), `<div class="q-slot" data-q="d1"></div>` (один вопрос), `<div class="selfcheck-grid" data-qgroup="selfcheck"></div>`. Готовые образцы блоков — в `lessons/K1/pages.html`.

Блок-схема: `<div class="flow-fig" role="img" aria-label="…" data-flow="start:Начало|io:Вывод: «…»|proc:Действие|cond:Условие?|end:Конец"></div>`. Код: `<pre class="code py">…</pre>` (подсветка и номера строк добавляются сами).

### data.js — задача
```js
p1: { kind: 'check', practice: true, star: false, title: 'Задача 1. Название', rows: 7,
  statement: '<p>Условие.</p><div class="sample-label">Образец вывода</div><pre class="sample">…</pre>',
  starter: '# Напишите программу под этой строкой\n',
  tests: [ { input: [], expected: 'строка 1\nстрока 2' } ],     // input — вводимые строки; hidden: true скрывает тест
  rules: [ { need: '^\\s*#', flags: 'm', text: 'В программе требуется комментарий (строка с #).', hint: '…' } ],  // требования к тексту программы: need / forbid (регулярное выражение; комментарии не учитываются, если не указан inComments: true) или comments: N (не меньше N комментариев)
  ladder: ['подсказка 1', 'подсказка 2', 'подсказка 3'],          // ровно 3 ступени, от общей к конкретной
  autoHints: [ { re: 'print\\s+["\']', text: 'После <code>print</code> требуются скобки.' },   // сработает при неверной проверке
               { countLt: { re: 'print\\s*\\(', n: 3 }, text: '…' }, { outputLacks: '"', text: '…' } ] }
```
- `kind: 'free'` — песочница без проверки (теория): `{ kind:'free', title, rows, statement, starter }`.
- Сравнение вывода: построчно; пробелы в конце строк, неразрывные пробелы, тире разных видов не учитываются; регистр и пробелы в начале строк учитываются.
- **Рисунок turtle**: тест `{ input: [], trace: { segments: [[x1,y1,x2,y2]…], relative: false, colors: false } }`; сравниваются отрезки как множества (порядок и направление не важны, смежные коллинеарные отрезки склеиваются). `colors: true` — цвета в 5-м элементе отрезка (`[0,0,100,0,"red"]`). В условии `<div class="trace-fig"></div>` рисует образец по `segments`; в теории статичный рисунок: `<div class="trace-fig" data-trace='[[0,0,100,0],…]'></div>`. Отрезки получать: `node tools/trace.js lessons/K3/ref_p1.py`.
- Вопросы: `QUESTIONS = { r1: { group:'review', mode:'instant'|'check'|'reveal', num:'Вопрос 1 из 3', text, code?, options:[{id,ok?,text|pre}], explain } }`; режимы: `instant` — вердикт сразу (Повторение), `check` — кнопка «Проверить», результат один раз (Разбор кода), `reveal` — плашка «Проверить себя» (Итог). Ровно один верный вариант, 4 варианта.

### solutions.json
```json
{ "p1": { "ref": "эталон", "alt": ["другой верный способ"], "wrong": ["типичное неверное решение 1", "…"] } }
```
Для каждой задачи `check` (включая `d2`, `d3`): эталон и **минимум 3 неверных решения** разных типов (порядок, пропуск, синтаксис, регистр, пробелы).

### methodichka.md
Разделы как в `lessons/K1/methodichka.md`: заглушки, подготовка, тайминг (40 мин), ход урока по частям (где остановить класс, что показать), ответы и эталонные решения, типичные ошибки (с текстом сообщения и ответом ученику), что смотреть в таблице результатов, особые случаи (в т. ч. для пятничной группы), отступления от спецификации.

## 6. Телеметрия, вход, восстановление (уже в движке)

Не менять. Для справки: вход по кодовому слову группы (проверяет Apps Script), «Пройти анонимно» (слово обязательно), пакеты событий раз в 30 с и при проверке/завершении/уходе/онлайне/очереди ≥ 25, дедупликация `(attemptId, seq)`, снимок раз в 60 с, восстановление из браузера/сервера/zip-файла, кнопки «Завершить занятие» и «Сохранить работу» (zip с JSON). События курса: `code_run`, `code_checked`, `hint_opened`, `task_solved`, `code_reset`, `section_opened`, `access_checked`, `session_restored`, `result_submitted`, `answers_checked`.

## 7. Чек-лист перед сдачей

- [ ] `node tools/build.js K<N>` и `node tools/verify.js K<N>` проходят (эталоны засчитываются, неверные нет, без ошибок консоли и внешних запросов, без горизонтальной прокрутки на 1440/1024/390).
- [ ] 3 + 2★ задач практикума по возрастанию сложности; 3 ступени подсказок у каждой; ровно один верный вариант у вопросов.
- [ ] Нет конструкций Python из будущих уроков (раздел 3). Нет «ты/вы/мы», риторических вопросов, примеров про Россию.
- [ ] Метатеги каталога заполнены (`lesson.json`), в `catalog:title` нет «Занятие N».
- [ ] Методичка: решения всех задач, типичные ошибки, тайминг.
- [ ] Закоммитить `lessons/K<N>/` и `K<N>/` (собранный HTML и методичку).

## 8. Настройки курса и публикация

`course.json`: `scriptUrl` (адрес веб-приложения Apps Script — уже задан), `courseUrl` (адрес сайта курса — `https://info-8-class.learn-it.app/`). После изменения: `node tools/build.js --all`. Кодовые слова хранятся только в свойствах скрипта, в репозиторий и HTML не попадают. `LOCAL_…` не публикуется (правило Learn-it: имя с подчёркиванием). Как забрать готовые файлы и опубликовать — `DEPLOY.md` (файлы копирует учитель, публикует проект публикации по стандартной схеме).

**Нельзя** запускать собранные страницы с боевым адресом скрипта и отправлять тестовые данные: события и снимки попадают в таблицы учителя на Google Диске. `tools/verify.js` блокирует сеть к Google и Яндексу сам; для ручной проверки отправки использовать макет `tools/gas_mock.js`.
